## 第一次接手：只读确认

在 `E:\Project\Project\easy-project` 执行：

```powershell
git status --short
git branch --show-current
git log -3 --oneline
git remote -v
```

再确认工具与技能可用性、当前额度、任务范围。不要为了“初始化”重置分支、迁移数据库、重装程序或重新生成 release。

个人技能的权威目录是 `E:\Project\Codex\skills`；本机应使用 `token-saver` 和 `easyproject-maintenance`。涉及审计、图标、原生桌面操作时分别读取相应技能。若伙伴环境没有这些技能，必须说明缺失并依照本包与仓库标准工作，不能假装已加载。旧维护技能的 project-context 中部分8月状态已过时，以当前仓库和本包的日期化证据为准。不要擅自改写全局技能或将 C 盘兼容链接替换为真实目录。

## 接手理解验收

新伙伴至少应能准确回答：

- 项目工作区和全局任务页有什么区别？当前调用链为何仍有 `crud_action`？
- 为什么代码检查通过、六资产核验、Windows基础试用和正式发布是不同结论？
- 哪些 UI 控件不能用原生 HTML 替代？如何避免 hover/focus 导致几何跳动？
- 数据库在哪里？备份恢复与 JSON 导入的版本要求有何不同？
- MCP 实现有 CRUD，为何当前客户端仍不能直接写真实数据？
- 额度不足如何保存、暂停与恢复？10%和5%门禁有什么区别？
- 四项已批准风险例外何时复查？为什么不能直接重跑 internal.2？
- 哪些是已交付功能，哪些只是候选或需要用户选择？

回答应引用仓库证据；不确定项明确写“未知/待确认”，不能用推断填充验收结果。
